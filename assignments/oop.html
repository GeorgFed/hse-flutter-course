Продуктовая постановка

Приложение хранит локальный каталог товаров и получает новую версию с бэкенда. Нужно найти id товаров, которые добавились, исчезли или изменились. Затем приложение сможет обновить только нужные карточки, а не перестраивать весь каталог.

Что должно получиться

старый List<Product> ─┐
                     ├─→ Map по id ─→ Set изменившихся id
новый List<Product> ─┘

Основной результат — корректная модель Product, сравнение списков, индекс Map и множество Set. Ошибка и логирование находятся в одном понятном месте.

ProductCartManager описывает три операции: сравнение списков, построение индекса и поиск изменений. Класс реализации студенты создают самостоятельно и возвращают из createProductCartManager(). Внизу того же lib/main.dart уже находится пример данных и вывод результата в консоль.

Выполняйте сверху вниз

Шаг 1. Сравнение Product

Переопределите operator == и hashCode.

  • сравните id, name, priceRubles, nullable category и tags;
  • tags — это список, поэтому сравнивайте его содержимое через ListEquality;
  • одинаковые товары обязаны иметь одинаковый hashCode;
  • проверка с Set<Product> покажет, согласованы ли equality и hash.

Шаг 2. Сравнение двух списков

Реализуйте sameProductList(...) через DeepCollectionEquality.

Обычное выражение firstList == secondList сравнивает два объекта List, а не их элементы. В этой задаче порядок товаров считается значимым.

Шаг 3. Индекс через Map

Реализуйте indexById(...):

  • ключ — Product.id, значение — Product;
  • повторяющийся id — некорректные входные данные;
  • перед FormatException запишите понятный лог с проблемным id;
  • после успеха залогируйте число товаров;
  • верните read-only Map.

Это единственное обязательное место обработки ошибки.

Шаг 4. Изменения через Set

Реализуйте findChangedIds(...):

  • постройте индексы старого и нового каталогов;
  • объедините их ключи в Set<String>;
  • оставьте id, для которых старый и новый Product не равны;
  • так автоматически найдутся добавленные, удалённые и изменённые товары;
  • не меняйте входные списки;
  • залогируйте итоговое число изменений.

Подсказки

  • Начинайте с одного теста и одного TODO.
  • Для hashCode используйте Object.hash(...).
  • Для списка tags уже подключён ListEquality.
  • Для списков товаров используйте DeepCollectionEquality.
  • Индекс удобно собирать обычным циклом в <String, Product>{}.
  • Все id удобно объединить так: <String>{...old.keys, ...new.keys}.

Референсы: equality, Map, Set, DeepCollectionEquality.

Мегаопционально

После обязательной части разделите изменения на added, removed, updated и верните их как record. Для обхода Map.entries попробуйте pattern. Эта часть не нужна для 2 баллов и не блокирует основное решение.

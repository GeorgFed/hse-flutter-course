Зачем сравнивать две версии каталога

Приложение уже показывает товары. С бэкенда приходит новый список. Вместо полного обновления нужно определить только карточки, состояние которых действительно изменилось.

Продуктовый поток

01 · БЫЛО

Локальный каталог

Версия, которую пользователь сейчас видит на экране.

→
02 · ПРИШЛО

Новый каталог

Актуальные товары, цены и свойства с бэкенда.

→
03 · РЕЗУЛЬТАТ

Set изменившихся id

Какие карточки добавить, удалить или обновить.

Четыре продуктовых сценария

1. Товар изменился

coffeeКофе · 159 ₽
→
coffeeКофе · 179 ₽

Результат: coffee попадает в Set — карточку нужно обновить.

2. Товар появился

—товара не было
→
waterВода · 50 ₽

Результат: water попадает в Set — карточку нужно добавить.

3. Товар исчез

teaЧай · 99 ₽
→
—товара больше нет

Результат: tea попадает в Set — карточку нужно удалить.

4. Товар не изменился

milkМолоко · 89 ₽
→
milkМолоко · 89 ₽

Результат: milk не попадает в Set — ничего делать не нужно.

Продуктовый смысл результата

Точечное обновлениеПриложение знает, какие карточки затронуты новой версией данных.
Предсказуемое поведениеДобавление, удаление и изменение описаны одним результатом — множеством id.
НаблюдаемостьЛоги показывают размер каталогов и число обнаруженных изменений.

Что увидим в консоли

Изменившиеся товары: [coffee, tea, water] LOG: Каталог: 2 товаров LOG: Каталог: 2 товаров LOG: Изменено: 3 товаров

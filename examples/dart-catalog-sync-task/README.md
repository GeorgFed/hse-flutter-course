# Синхронизация каталога на Dart 3

## Зачем это делаем

Приложение хранит локальный каталог товаров и периодически получает новую версию с бэкенда. Нужно понять, какие товары добавились, исчезли или изменились, чтобы обновить только нужные карточки.

## Что нужно сделать

Интерфейс `ProductCartManager` уже описывает требуемые операции. Последовательно завершите модель `Product`, создайте собственный класс с `implements ProductCartManager` и верните его из `createProductCartManager()`:

1. Сравнение двух `Product` через `operator ==` и `hashCode`.
2. Глубокое сравнение двух `List<Product>`.
3. Индекс каталога `Map<String, Product>` с проверкой дублей и логированием.
4. Множество `Set<String>` с id изменившихся товаров.

В обязательной части нет records, patterns, async, Flutter и сложной архитектуры.

## Выберите способ запуска

- **Dart уже установлен:** проверьте `dart --version` и переходите к VS Code ниже.
- **Есть Flutter:** Dart уже входит в него. Для этой задачи достаточно работающей команды `dart`; Android Studio, Xcode, эмулятор и `flutter doctor` не нужны.
- **Ничего не установлено:** установите только Dart SDK и VS Code по шагам ниже.
- **Не успеваете установить или нет прав администратора:** откройте раздел «DartPad без установки». Для него нужен браузер и доступ к dartpad.dev.

Для локального проекта нужен **Dart >=3.9.0 и <4.0.0**: эта граница учитывает зафиксированные зависимости тестов. Проверено на Dart **3.9.2**. Берите актуальную stable-версию Dart 3. Расширение редактора не заменяет SDK.

## Установка Dart с нуля

Самый одинаковый для всех ОС путь — официальный [архив SDK](https://dart.dev/get-dart/archive): stable → ваша ОС → архитектура → Dart SDK ZIP. Windows/Linux на обычном Intel/AMD — x64; Mac с Apple Silicon — arm64, с Intel — x64. На Windows ARM выбирайте arm64. Архитектуру Mac можно посмотреть в «Об этом Mac», Windows — в «Параметры → Система → О системе», Linux — командой `uname -m` (`x86_64` = x64, `aarch64` = arm64).

**Windows, без установки Flutter:**

1. Распакуйте архив, например в `C:\Users\ВАШЕ_ИМЯ\development\dart-sdk`. Убедитесь, что внутри есть `bin\dart.exe`. Не запускайте из ZIP.
2. Найдите в меню Пуск «Изменение переменных среды текущего пользователя». В пользовательской переменной `Path` нажмите «Изменить → Создать» и добавьте полный путь `C:\Users\ВАШЕ_ИМЯ\development\dart-sdk\bin`. Существующие записи не удаляйте.
3. Закройте и заново откройте PowerShell и VS Code. Выполните `dart --version`. Если команда не найдена, проверьте `where.exe dart` и путь именно к папке `bin`.

**macOS / Linux, через ZIP:**

1. Распакуйте `dart-sdk` в `development` внутри домашней папки.
2. Откройте Terminal и выполните:

```bash
export PATH="$HOME/development/dart-sdk/bin:$PATH"
dart --version
```

3. Чтобы путь сохранялся после закрытия терминала, добавьте строку `export PATH=...` выше в `~/.zshrc` для zsh или `~/.bashrc` для bash. Это добавление строки, не замена всего файла. Затем откройте новый терминал и перезапустите VS Code.
4. `which dart` должен указывать на установленный SDK. Если macOS блокирует скачанный файл, используйте официальный пакетный способ ниже; не отключайте системную защиту целиком.

Если уже используете Homebrew, Chocolatey или apt, можно установить Dart привычным пакетным способом по [официальной инструкции для своей ОС](https://dart.dev/get-dart). Для этой пары не нужно сначала устанавливать пакетный менеджер. Если Flutter уже установлен, добавьте в PATH его папку `bin` — второй SDK не требуется.

## VS Code: от открытия проекта до проверки

1. Установите [Visual Studio Code](https://code.visualstudio.com/download).
2. Откройте Extensions (`Ctrl+Shift+X`, на Mac `Cmd+Shift+X`), найдите **Dart** от **Dart Code**, идентификатор `Dart-Code.dart-code`, и установите. В проекте есть рекомендация этого расширения. Поддержка Flutter для этой задачи необязательна.
3. Выберите **File → Open Folder** и папку с `pubspec.yaml`. Если VS Code спрашивает о доверии, разрешайте его только для скачанного вами репозитория курса.
4. Откройте **Terminal → New Terminal**. Выполните по одной команде:

```bash
dart --version
dart pub get
dart analyze
dart test
dart run lib/main.dart
```

5. `pub get` должен скачать зависимости; `analyze` у исходного starter должен завершиться без замечаний. До вашего решения **проходит 1 тест из 8, остальные 7 падают**. `UnimplementedError` при запуске `main` — ожидаемый TODO, а не поломанная установка. Ошибки загрузки пакетов, неизвестный `dart` и неверная версия SDK — проблемы окружения, их нужно исправить до работы.
6. Редактируйте **lib/main.dart**. Начните с `Product`, затем создайте класс с `implements ProductCartManager` и верните его из фабрики. Сохраняйте файл перед запуском.
7. Для запуска выберите **Run and Debug → Каталог: main → F5**. Конфигурация уже находится в `.vscode/launch.json`. `Ctrl+F5` — запуск без отладчика. Результат выводится в Terminal. Flutter-устройство выбирать не нужно.
8. Для отладки поставьте красную точку слева от строки, нажмите F5; используйте Step Over и панель Variables. На незаполненном TODO отладчик может остановиться на исключении — это ожидаемо.
9. Тесты можно запускать через `dart test`, ссылку Run над тестом или панель Testing. Для одного сценария: `dart test --plain-name "Set удаляет дубликаты равных Product"`.
10. Повторяйте цикл: один TODO → сохранить → соответствующий тест → все тесты → анализатор. Форматирование: **Format Document** или `dart format lib/main.dart`.

Если VS Code не нашёл SDK, откройте Settings и найдите `Dart: Sdk Path`. Укажите папку **dart-sdk**, не `bin`; для Dart внутри Flutter — `flutter/bin/cache/dart-sdk`. Перезагрузите окно командой **Developer: Reload Window**. Терминал и расширение должны использовать одну версию SDK.

В учебной практике агенты запрещены: отключите AI Chat и генерацию/дописывание кода агентами. Обычное дополнение имён, подсказки типов и документация Dart разрешены.

Готово, когда `dart analyze` без замечаний, **8/8 тестов зелёные**, а пример печатает:

```text
Изменившиеся товары: [coffee, tea, water]
```

Также будут три сообщения `LOG`. Точный текст логов может отличаться при сохранении требований задания.

## DartPad без установки — запасной маршрут

1. Откройте [dartpad.dev](https://dartpad.dev/), создайте новый **Dart** snippet, не Flutter.
2. Откройте [dartpad/main.dart](dartpad/main.dart) в репозитории и нажмите **Raw**. Выделите и скопируйте **весь файл**. Можно открыть тот же файл из скачанного ZIP текстовым редактором.
3. Замените весь пример в DartPad этим кодом и нажмите **Run**. Ничего устанавливать, создавать `pubspec.yaml` или запускать `pub get` здесь не нужно. Импорт `package:collection/collection.dart` оставьте: `collection` входит в поддерживаемые DartPad пакеты.
4. Исходная версия выводит **CHECKS: 1/8 passed; 7 failed**. Это подтверждает, что код компилируется и проверки выполняются; дальше нужно реализовать TODO в верхней части файла.
5. Меняйте только модель, свою реализацию и фабрику. `demoMain` — готовый пример, нижняя часть файла — те же восемь сценариев и обвязка проверки. Не удаляйте их. Нажимайте Run после каждого шага; ошибки выводятся как `FAIL` с названием сценария.
6. Цель — **CHECKS: 8/8 passed; 0 failed**, затем строка `[coffee, tea, water]` и логи. Самопроверка использует явные условия, а не `assert`, поэтому работает в веб-сборке.
7. Перед закрытием вкладки скопируйте весь код в локальный файл `catalog-dartpad.dart`. Не рассчитывайте, что вкладка сохранит работу. Передайте преподавателю файл с кодом, не только скриншот.
8. После установки SDK перенесите свои изменения из верхней части в `lib/main.dart` обычного starter. Не копируйте туда обвязку проверок и второй `main`. Выполните `dart analyze` и `dart test` для окончательной локальной проверки.

DartPad запускает один файл; обычный `test/catalog_test.dart` напрямую туда не вставляют: в нём пакетный импорт и `package:test`. Для этого и подготовлен отдельный файл со встроенными проверками. Зелёная веб-самопроверка не отменяет проверку кода и объяснение решения; при отсутствии SDK преподаватель может прогнать сдачу локально по той же рубрике.

DartPad требует интернета и доступности его сервиса; это запасной путь при отсутствии SDK, не офлайн-режим. Если `collection` не находится или Run зависает, сохраните код, создайте чистый Dart snippet и повторите. Если сервис недоступен, используйте локальный маршрут или сообщите преподавателю — не тратьте всю практику на настройку сети.

## Частые проблемы

| Симптом | Что сделать |
|---|---|
| `dart: command not found` / «не является командой» | Проверить PATH до `dart-sdk/bin`, закрыть и заново открыть терминал и VS Code. |
| SDK constraint / version solving failed | Выполнить `dart --version`; нужен Dart 3.9+. Обновить SDK, не удалять ограничения и тесты. |
| `No pubspec.yaml file found` | Перейти в корень распакованного проекта, где находится этот файл. |
| `Target of URI doesn't exist` для package | Запустить `dart pub get` в корне; дождаться успеха, перезагрузить окно VS Code. |
| `pub get` сообщает сетевую ошибку | Нужен доступ к pub.dev и хранилищу пакетов. Не менять код задания; попробовать доступную сеть или DartPad. |
| F5 просит конфигурацию / устройство | Открыть корень проекта и выбрать «Каталог: main»; использовать расширение Dart, не Code Runner. |
| `UnimplementedError`, 1/8 в начале | Ожидаемое состояние starter. Установка успешна, начинайте TODO. |
| Тесты не видят изменения | Сохранить файл; убедиться, что редактируете ту же папку, из которой запускаете тесты. |

## Обработка ошибки и логирование

`indexById` — единственное место с обязательной ошибкой: повторяющийся `Product.id` означает некорректный каталог. Перед `FormatException` запишите сообщение через необязательный `log` callback. После успешного индексирования и после сравнения каталогов также оставьте короткий лог.

Внизу `lib/main.dart` уже находится один консольный пример. После реализации интерфейса он должен вывести изменившиеся id и три коротких лога.

## Оценка

- **0 баллов:** проект не собирается, проходят меньше 4 из 8 тестов или студент не может объяснить решение.
- **1 балл:** проходят 4–7 тестов; модель сравнивается и работает хотя бы одна из структур `Map`/`Set`; студент объясняет реализованную часть.
- **2 балла:** проходят все 8 тестов и `dart analyze`; студент объясняет equality/hashCode, deep equality, Map, Set, обработку дубля и назначение логов.

Добавляем пакет командой

  • pub add выбирает новейшую версию, совместимую с нашим SDK.
  • Пишет ограничение с кареткой и обновляет pubspec.lock.
  • Коллега после clone выполняет flutter pub get.

flutter pub add url_launcher

# инструмент только для разработки:
flutter pub add dev:flutter_lints

pubspec: из чего состоит

YAML
environment:
  sdk: '>=3.9.0 <4.0.0'

dependencies:
  flutter:
    sdk: flutter
  city_catalog:
    path: packages/city_catalog
  url_launcher: ^6.3.2

dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^6.0.0

# dependency_overrides: — только временно
  • environment — версии Dart и Flutter.
  • dependencies — нужны приложению во время работы.
  • dev_dependencies — только при разработке.
  • dependency_overrides — временная замена, часть 5.

Используем API пакета

Dart
import 'package:url_launcher/url_launcher.dart';

Future<void> openMap(BuildContext context) async {
  final opened = await launchUrl(city.mapUrl);
  if (opened || !context.mounted) return;
  ScaffoldMessenger.of(context).showSnackBar(
    const SnackBar(
      content: Text('Не удалось открыть карту'),
    ),
  );
}
  • import открывает API пакета в файле.
  • launchUrl возвращает bool: открылось или нет.
  • После await — context.mounted: это StatelessWidget.

КомандаЧто делает

Lock в приложении и в пакете

Приложение

Lock фиксирует всё дерево. Коммитим: сборка повторяется у всех и в CI.

Пакет-библиотека

Его lock используется только при разработке самого пакета. Приложение выбирает версии своим resolver.

dependencies:

Частый случай: пакет требует новый SDK

dependency_overrides

YAML
dependency_overrides:
  url_launcher_platform_interface: 2.3.2
  city_catalog:

  • Заставляет взять указанную версию или источник вопреки чужим ограничениям.

  • Совместимость не доказывает: проверяем сценарии и убираем, как только выйдет исправление.

Как Dart говорит с платформой

  • Dart-часть вызывает метод нативной части через канал платформы.
  • Нативный код выполняет действие и возвращает результат в Future.
  • Новый плагин — полный перезапуск: hot reload не пересобирает нативный код.
  • Нет реализации для платформы — MissingPluginException.

Подмена плагина в тесте

Dart
class FakeLauncher extends Fake
    with MockPlatformInterfaceMixin
    implements UrlLauncherPlatform {
  FakeLauncher(this.result);
  final bool result;
  final opened = <String>[];

  @override
  Future<bool> launchUrl(
    String url,
    LaunchOptions options,
  ) async {
    opened.add(url);
    return result;
  }
}

// В тесте:
UrlLauncherPlatform.instance = FakeLauncher(false);
  • Тест не открывает браузер: подменяем реализацию платформы.
  • Проверяем и успех, и сообщение «Не удалось открыть карту».
  • Для этого и нужны dev-пакеты из части 4.

Зачем делить проект на пакеты

  • Границы видны в pubspec: кто от кого зависит.
  • Внутренности пакета в src/ снаружи не импортируют.
  • Логика на чистом Dart тестируется быстро: dart test.
  • Пакет переиспользуют другие приложения и команды.

Итог

  • Задача → пакет на pub.dev → pub add → import.
  • pubspec — что разрешено, lock — что выбрано; приложение коммитит оба.
  • Конфликт — пересечение диапазонов; override только временно.
  • Плагин = Dart API + код платформы; после добавления — полный перезапуск.
  • Логику без UI выносим в свой пакет и подключаем по path.

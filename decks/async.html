02Асинхронность · определение

Что такое асинхронность

Асинхронность позволяет продолжать работу, пока другая операция ждёт результата.

  • Синхронное ожидание останавливает текущий поток.
  • При ожидании сети приложение может обрабатывать другие события.
  • В Dart для этого используются колбэки, Future и async/await.

03Dart под капотом · Event Loop

Event Loop: цикл событий приложения

Event Loop — цикл, который выбирает готовую задачу и выполняет её в приложении.

  • Как диспетчер: берёт готовую работу из очереди и передаёт её на выполнение.
  • Синхронный обработчик работает до конца; другой обработчик его не прерывает.
  • Асинхронная операция начинает ждать, а её готовый результат обрабатывается позже.

Как устроен сам цикл

После текущего кода цикл обрабатывает microtasks, затем один event и снова проверяет очереди.

  • Microtasks обрабатываются до опустошения очереди.
  • После одного event цикл снова проверяет microtasks.
  • Программа завершается, когда нет ни готовой работы, ни активных источников событий.

Запуск простого приложения

main выполняется первым; отложенные функции начнут работу после текущего кода.

Dart
import 'dart:async';
void main() {
  print('start');
  scheduleMicrotask(() => print('micro'));
  Timer.run(() => print('timer'));
  print('end');
}
  • main печатает start и end.
  • Затем вызывается microtask и печатает micro.
  • После неё цикл берёт событие таймера и печатает timer.

Как Dart узнаёт о готовности сети

Среда выполнения Dart получает уведомление от ОС или браузера и доставляет готовую работу в цикл.

  • При начале запроса среда выполнения регистрирует ожидание результата.
  • Система сообщает о готовности сети; обработчик читает данные и завершает Future.
  • Ожидающий Future сам не проверяет сеть в цикле.

Когда Dart создаёт microtasks

Microtask нужна, чтобы вызвать короткий обработчик позже, но до следующего event.

Dart
print('before');
Future.value(1).then((value) => print(value));
scheduleMicrotask(() => print('notify'));
print('after');
  • Обработчик уже готового Future.value выполняется позже, через microtask.
  • Future.microtask и scheduleMicrotask явно добавляют функции в эту очередь.
  • Асинхронный StreamController также может использовать microtasks для доставки; это не правило всех Stream.

10Dart под капотом · Event Loop

Как microtasks задерживают события

Цепочка microtasks может не давать циклу перейти к таймерам, вводу и отрисовке.

Dart
import 'dart:async';
void main() {
  var left = 3; // Убрали лимит — получили starvation.
  void chain() {
    print('microtask');
    if (--left > 0) scheduleMicrotask(chain);
  }
  Timer.run(() => print('event'));
  scheduleMicrotask(chain);
}
  • Microtask, которая создаёт следующую microtask, продлевает приоритетную очередь.
  • Очередь может содержать всего одну задачу и всё равно никогда не опустеть.
  • Длинные вычисления выносят в isolate — отдельную область исполнения; короткие части работы могут уступать управление через Future.delayed(Duration.zero).

Колбэк: определение и пример

Колбэк — функция, которую передают другому коду для вызова в нужный момент.

Dart
import 'dart:async';

void fetchName(void Function(String) onDone) {
  Timer.run(() => onDone('Alex'));
}

void main() {
  fetchName((name) => print(name));
  print('UI продолжает работу');
}
  • В примере fetchName передаёт функцию таймеру.
  • После регистрации main продолжает работу.
  • Завершение fetchName не означает, что переданная функция уже вызвана.

14Future · один результат

Future<T>

Future<T> представляет одно значение типа T или ошибку, которые станут доступны позже.

Dart
Future<int> performAsyncOperation() =>
    Future<int>.delayed(
      const Duration(seconds: 2), () => 42,
    );

void main() {
  performAsyncOperation()
      .then<void>((result) {
        print('Результат: $result');
      })
      .catchError((Object error) {
        print('Ошибка: $error');
      });
}
  • then получает успешный результат.
  • catchError может обработать ошибку предыдущей части цепочки.
  • В этом примере Future завершается значением 42 после задержки.

Future: состояния

Пока результат не готов, Future остаётся незавершённым; после завершения его исход уже не меняется.

  • Uncompleted: результат ещё не получен.
  • Data: получено значение.
  • Error: получена ошибка и сведения о месте её возникновения.

onError и catchError: где возникла ошибка

onError внутри then обрабатывает ошибку исходного Future; catchError ниже — необработанные ошибки предыдущей цепочки.

Ошибка до then · вывод: onError
Future<void>.error('load failed')
    .then<void>(
      (_) {},
      onError: (Object e) =>
          print('onError'),
    )
    .catchError((Object e) =>
        print('catchError'));
Ошибка внутри then · вывод: catchError
Future.value(1).then<void>(
  (value) {
    throw StateError('parse failed');
  },
  onError: (Object e) =>
      print('onError'),
).catchError((Object e) =>
    print('catchError'));

then создаёт новый Future; ошибка его обработчика попадёт туда, где её сможет поймать следующий catchError.

Timer: ожидание без блокировки потока

Timer сохраняет функцию и срок вызова; ожиданием занимается среда выполнения Dart.

Dart
import 'dart:async';
void main() {
  Timer.run(() => print('event'));
  scheduleMicrotask(() => print('microtask'));
  print('sync');
  Timer.periodic(const Duration(milliseconds: 5), (t) {
    print('tick ${t.tick}');
    if (t.tick >= 2) t.cancel();
  });
}
  • Функция таймера выполняется в том же Dart-isolate, где Timer был создан.
  • Задержка задаёт срок готовности: занятый цикл может вызвать функцию позже.
  • Timer.periodic не ждёт завершения Future, возвращённого его функцией.
  • cancel предотвращает следующие вызовы.

Timer в Dart VM: срок → сообщение → колбэк

Для ненулевой задержки Dart VM хранит время вызова и просит встроенный обработчик событий ждать этого срока.

  • VM сохраняет функцию и вычисляет время её вызова.
  • Обработчик событий ждёт уведомление ОС или истечение ближайшего срока.
  • VM получает служебное сообщение; в цикле Dart вызываются готовые функции таймеров.

Timer.run сразу ставит событие без ожидания срока; в браузере таймеры опираются на его API, например setTimeout.

Dio: готовый AuthInterceptor

AuthInterceptor добавляет заголовок авторизации перед отправкой запроса.

Dart
class AuthInterceptor extends Interceptor {
  AuthInterceptor(this.readToken);
  final String? Function() readToken;
  @override
  void onRequest(RequestOptions options,
      RequestInterceptorHandler handler) {
    final token = readToken();
    if (token != null) {
      options.headers['Authorization'] = 'Bearer $token';
    }
    handler.next(options);
  }
}
  • Токен читается перед запросом.
  • handler.next передаёт изменённый запрос дальше.
  • Заголовок с токеном не выводится в журнал.

Простой GET: профиль на Dio

Dio использует настроенные baseUrl и таймауты; функция добавляет токен и создаёт DTO из ответа.

Dart
Future<ProfileDto> fetchProfile(
  Dio dio, String token,
) async {
  try {
    final response = await dio.get<Map<String, dynamic>>(
      '/v1/me', options: Options(headers: {
        'Authorization': 'Bearer $token',
      }),
    );
    final data = response.data ??
        (throw Exception('Пустой ответ'));
    return ProfileDto.fromJson(data);
  } on DioException catch (error) {
    final message = error.response?.statusCode == 401
        ? 'Требуется вход' : 'Ошибка загрузки';
    throw Exception(message);
  }
}
  • В примере ожидается JSON с id и name.
  • При 401 просим войти; другие DioException сообщают об ошибке загрузки.
  • Клиент Dio закрывает его владелец.
